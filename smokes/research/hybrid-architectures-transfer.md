## Bottom line
1. **No published evidence says a hybrid SSM / linear-attention model beats a 33M encoder + linear head at 1-10 rows per label.** I found no few-shot classification number at <=1B for Qwen3.5 small, Falcon-H1, Granite-4.0-H, LFM2, Zamba2, RWKV-7 or any Titans / TTT model. One hybrid <=1B sentence embedder does exist, Liquid AI's LFM2.5-Embedding-350M (released 2026-06-18, vendor-reported, no MTEB scores yet), see section 5. The repo's own result (S22: bge-small + LR 0.80/0.92/0.97 at k = 1/3/10 beats every 0.5B decoder arm) is the only head-to-head, and it used a pure-attention decoder.
2. **The one thing the hybrids add that an encoder lacks is a fixed-size recurrent state that can hold a prefilled support set**, so "read k rows per label once, snapshot the state, answer every query from the snapshot" has constant per-query cost. That is a latency / replay property, not a label-efficiency one. The ICL literature supports only a weaker claim: pure Mamba is weaker at ICL on language benchmarks (Halloran et al.: ~38% of the Transformer's ICL gain; Jamba ablation: pure Mamba breaks the output format on IMDB, a hybrid with 1 attention layer in 8 recovers it), while MambaFormer (Park et al.) and Grazzi et al. (2402.03170) find SSMs match Transformers on regression ICL (section 3).
3. **Test-time training and Titans-style memory reduce, mathematically, to what S24 already tested.** A delta-rule / TTT memory fed frozen embeddings is an online least-squares classifier (test-time-regression framework), and a softmax read over stored rows is a modern Hopfield read. S24 found the Hopfield read-out ~ LR; seeding it with LLM-written examples gave 0.89 acc / 0.50 coverage at k=1, but that is still behind S17's LR trained on the LLM-written rows (0.80 coverage at k=1; 80/87/95% at k=1/3/10), which is the best measured warm start. Expect a Titans memory head to tie LR; the bar for smokes A and B is S17's LR-on-LLM-rows, not the seeded Hopfield.
4. **Determinism is currently worse for the hybrids, not better.** vLLM batch-invariant mode rejects Gated DeltaNet (Qwen3.5 / 3.6 / 3.8) at startup; the fix (PR 45819) is open and showed 15 of 16 prompts bitwise identical, 1 diverging. Mamba2 hybrids (Granite-4.0-H, Nemotron-H) have an open PR. A pinned fixed-shape batch-1 profile on HF / fla kernels is the only route that is deterministic today, and it must be measured, not assumed.
5. **Recommended smokes (all < $1, none needs more than one pod hour). Run first: (0) embedder swap, LFM2.5-Embedding-350M + LR vs bge-small + LR on the S23 protocol, CPU, $0. If RunPod and Hugging Face stay blocked, use a CPU EC2 instance as a network relay/proxy (user request; 256 vCPU quota per FINDINGS, no GPU quota needed) to run `smokes/pod.py` against RunPod and to pull HF weights, which unblocks C as well:** (A) Qwen3.5-0.8B in-context k-shot with a prefilled, snapshotted state vs the S1 LR and S17's LR-on-LLM-rows on the S23 tasks; (B) delta-rule / Hopfield memory head on frozen bge-small embeddings vs LR, S17's LR-on-LLM-rows and the S24 seeded Hopfield; (C) batch-invariance and state-snapshot replay test of Qwen3.5-0.8B and Granite-4.0-H-350M, S7/S8 protocol. Smoke B is the most informative per dollar; A is the only one that could surprise.
6. Honest prior: A loses to LR at 12-15 labels (the S23 protocol; add a 77-label Banking77 arm if the 77-label question matters), B ties, C shows the hybrids need the pinned profile. The value of running them is closing the "did we leave a family untested" question with numbers, and a determinism fact sheet for the certificate.

Reading (my inference, not a source claim): with frozen embeddings x and one-hot labels y, a delta-rule memory W <- W + beta (y - Wx) x^T is the Widrow-Hoff / online ridge classifier; with a decay gate it is the same with forgetting. Its capacity is d_k key slots per head, and bge-small has d = 384, so 77 labels x k rows fits only if rows are near-orthogonal; beyond that interference appears, which is what LR's global fit already handles optimally. A Hopfield / softmax read over stored rows is S24's Hopfield student. So the "state as memory" head is a re-parameterisation of arms already measured, and the only extra lever it brings, a different optimiser, is what the regression view says LR already solves in closed form.

Reading: a recurrent state has fixed shape, which helps cost (no growing KV cache, constant memory per sequence; Qwen3.5 0.8B keeps KV only for 6 of 24 layers per the secondary source) but it does not make the numerics deterministic: the chunked scan and the conv state depend on how prefill is split, so a state snapshot of a prefilled support set is reproducible only if the chunk size and kernel are pinned. For the certificate and byte-replay contract the hybrids are strictly harder than the 33M encoder, whose forward pass is a few fixed-shape matmuls that S7 already showed can be byte-identical at batch 1.

## 7. (e) Connecting S24 (Hopfield / memory students) to these models
- Modern Hopfield read = softmax attention over stored patterns (https://arxiv.org/pdf/2008.02217), so S24's seeded Hopfield memory already is "attention with a support-set memory"; making the memory recurrent (delta rule) only changes how it is written, not how it classifies.
- Associative-memory layers in hybrids are the same objects at a different scale (test-time-regression view, https://arxiv.org/pdf/2501.12352). Their capacity limit (about d_k associations per head) is a reason to prefer an explicit store (rows + Hopfield read) for a trace store that grows to thousands of rows; the explicit store is also exactly replayable and auditable (you can list which rows voted), which an opaque state is not.
- The only transferable idea is **write rule**, not architecture: error-driven writes (store a row only when the memory mispredicts it, the delta rule's behaviour) could keep the seeded Hopfield memory small. That is a data-structure tweak testable in smoke B.

## Three cheap smokes
Common protocol: the S23 five-task, 12-15-label set and Banking77-12 sub-tasks, k = 1, 3, 10 rows per label, 3 draws, group-held-out tasks; metrics accuracy and certified coverage at a 5% budget (grid certificate, `common.py`); baselines S1 LR on bge-small, **S17 LR trained on LLM-written rows (best measured warm start: 0.80 coverage at k=1)**, S24 seeded Hopfield (0.50 at k=1), and at k=1 the S23 TK-KNN / Sinkhorn probes (0.89-0.91 acc, 0.35-0.56 coverage). Calibration rows stay a random sample, never selected.

**0. Embedder swap (CPU, $0).** LFM2.5-Embedding-350M (sentence-transformers) + LR vs bge-small + LR, same protocol, also with S17's LLM-written rows as training. Prediction: ties or slightly beats bge-small on acc at 10x the parameters; certified coverage is the real metric.

**A. Qwen3.5-0.8B in-context k-shot with a snapshotted state (<= $0.30, one 4090 pod-hour fraction; or CPU if tokens fit).**
- Prompt: label list as short codes, then k support rows per label (12-15 labels x k=3 ~ 3-5k tokens), then the query; read the next-token distribution over the label codes (no generation, so the readout is one forward). Arms: (1) plain ICL, (2) retrieval-selected demonstrations (Milios-style, nearest 20 rows by bge-small), (3) prefill support once, copy the recurrent + KV state, answer every query from the copy (expected identical to (1) up to numerics; measures the speed-up and the replay delta), (4) the same with LLM-written examples as support (S17 arm).
- Also record per-query latency vs the 33M encoder and the number of distinct outputs across 3 chunk sizes.
- Prediction: accuracy below LR at 12-15 labels for k<=3, further below at 77 labels; arm (4) closest. If arm (2) is within 2 points of LR at k=3, that is the first hybrid-positive result.

**B. Delta-rule / Titans-style memory head on frozen bge-small embeddings (CPU, $0, ~20 min).**
- Arms: ridge / LR (S1), seeded Hopfield (S24), delta rule W <- W + beta(y - Wx)x^T single pass and 5 passes, with decay gate, with error-driven writes only (store a row only if mispredicted), and a small Titans-style MLP memory updated by one gradient step per row with momentum (lucidrains-style reimplementation or 60 lines of torch). Seed each with the LLM-written examples as in S24.
- Measures whether any memory write rule beats LR or the seeded Hopfield and whether error-driven writes shrink the store without loss.
- Prediction: ties LR from k=3; error-driven writes keep ~equal accuracy with fewer stored rows. A win at k=1 must be measured against S17's LR-on-LLM-rows (0.80 coverage), not only the seeded Hopfield (0.50).

**C. Determinism and state-snapshot replay of the two smallest usable hybrids (<= $0.15, ~20 pod-minutes, CUDA GPU).**
- Models: Qwen3.5-0.8B (GDN) and granite-4.0-h-350m (Mamba2). Protocol of S7/S8: 1000 batch-1 passes from 8 CUDA streams, same input in random batch sizes 1-8, fixed vs dynamic padding, 3 prefill chunk sizes, fla kernels vs torch reference; count distinct output byte-strings of the next-token logits and of a prefilled state snapshot. Optionally `VLLM_BATCH_INVARIANT=1` to confirm the GDN startup error and the Mamba2 behaviour on the installed version.
- Prediction: 1 distinct at fixed batch 1 and a pinned chunk size; many distinct across chunk sizes and batch sizes; confirms the "pin the execution profile" rule extends to hybrids.

Free add-on: last-token / mean-pool embeddings from Qwen3.5-0.8B and granite-4.0-h-350m + LR on the same tasks (S21-style probe), next to the smoke 0 embedder; expected to lose or tie at 25-45x the parameters.
