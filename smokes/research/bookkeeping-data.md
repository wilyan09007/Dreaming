# Bookkeeping demo data: research (2026-10-17)

Method: HF Hub API + datasets-server, GitHub API, OpenML/Mendeley/Zenodo public endpoints, plus WebSearch/WebFetch. Sizes and licenses below come from the cited API/card unless marked unverified. Downloads were tested only as far as HTTP HEAD or a streamed first rows; no bulk data was downloaded except the 0.5 MB MoneyData file.

## Summary

- Nothing open links bank descriptors, vendors, invoices and anomaly labels together. Any end-to-end bookkeeping demo has to be assembled; the join (invoice <-> transaction <-> vendor) must be generated by us.
- (a) categorize_transaction: best no-login pair is MoneyData (REAL, 8,314 UK rows, 6,543 labeled, CC BY 4.0, but only 909 distinct descriptors) for realism/eval, plus DoDataThings/us-bank-transaction-categories-v2 (synthetic, 68,000 rows, MIT, 17 labels, ungated) for volume. The 4.5M-row mitulshah set is GATED (needs HF login) and has unclear provenance: skip.
- (b) vendor_lookup ground truth: osmlab/name-suggestion-index (BSD-3-Clause; 17,861 brand entries, 16,885 of 48,483 total entries carry a Wikidata id, with `matchNames` aliases; 11.9 MB json via jsDelivr) is the best no-login source. Chains only, so add a few hundred SaaS/B2B vendors ourselves.
- (c) invoices: no dataset pairs invoices with bank lines. For field-level JSON ground truth use katanaml-org/invoices-donut-data-v1 (MIT, 501 invoices) and SROIE/CORD (CC-BY-4.0 per HF cards) as realism references; but generate our own text-only invoices from the synthetic ledger so matching labels exist by construction. RVL-CDIP is images plus a 16-class doc label only (38.8 GB): useless here.
- (d) anomaly labels: no bookkeeping-style anomaly set exists. Best no-login real-format sets: IBM TabFormer (278.6 MB, 24M rows, has MCC and Is Fraud, but merchant name is an integer hash), ULB creditcard via OpenML (PCA features, 284,807 rows, 492 fraud), PaySim via HF mirror. Recommend rule-injected anomalies in the synthetic ledger instead (labels have a known mechanism).
- Recommendation: SYNTHESIZE, hybrid. Template descriptors from real merchant lists (NSI + DoDataThings formats), use a cheap LLM only for long-tail merchants, free text and edge cases. Order of magnitude for a 20k-row labeled ledger plus 2k invoices on OpenRouter (2026-10-17 prices): about $1 on claude-haiku-5.5, about $15 on claude-sonnet-5.5 (estimates, assumptions in Numbers).
- Plan-relevant point: in Dreaming the labels for the predictor are the frontier model's own outputs. Human-style ground-truth labels are only needed to evaluate the teacher. So realism of INPUT distribution (descriptor formats, merchant long tail, base rates) matters more than gold labels.
- Kaggle (login required, flagged): PaySim original, ULB creditcard original, IEEE-CIS, Sparkov/kartik2112 fraud set, IBM AML original. All have usable no-login mirrors (HF/OpenML/GitHub) listed below, with license-provenance caveats.

### B. Vendor / merchant ground truth (for vendor_lookup)

- Name Suggestion Index: https://github.com/osmlab/name-suggestion-index (BSD-3-Clause per GitHub API, last push 2026-10-17). npm `name-suggestion-index@8.0.20260918`; `dist/nsi.min.json` 11.9 MB at https://cdn.jsdelivr.net/npm/name-suggestion-index@latest/dist/nsi.min.json. I parsed it: 48,483 items (operators 24,312; brands 17,861; transit 5,816; flags 494); 16,885 have `brand:wikidata`. Item fields: displayName, id, locationSet (country include list), matchNames (aliases), tags (brand, brand:wikidata, shop/amenity type). Gives deterministic {canonical name, Wikidata Q-id, OSM category, country}. Weakness: brick-and-mortar chains, almost no SaaS/professional-services vendors.
- Overture Maps Places: https://docs.overturemaps.org/guides/places ; ~81.5M places, release 2026-09-23.1, anonymous S3 `s3://overturemaps-us-west-2/release/2026-09-23.1/theme=places/type=place/` (AWS registry says no AWS account required: https://registry.opendata.aws/overture/). Fields: names, brand, websites, confidence, `taxonomy`/`basic_category` (`categories` removed in Sept 2026 release). Licenses per source: CC0 (AllThePlaces), Apache-2.0 (Foursquare), CDLA-Permissive-2.0 (Meta, Microsoft, others). Overkill for a demo; use bbox download only. Useful if vendor_lookup should return address/website.
- MCC codes: https://github.com/greggles/mcc-codes (Unlicense; mcc_codes.csv 94 KB/json). TabFormer rows carry MCC, so MCC -> category mapping is free there.
- Plaid sandbox / Teller sandbox are NOT vendor ground truth (fixtures). See D.
- Wikidata SPARQL could supply SaaS vendors with ids (not tested here; unverified).

Assessment: none of these gives bookkeeping anomalies (duplicate bill, vendor/amount drift, split invoices). Rules to inject into our own ledger: exact duplicate (vendor, amount) within N days; amount > k x vendor rolling median; first-time vendor with round amount; weekend/holiday posting; sum of splits just under approval threshold; missing invoice for large debit. Base rate 1-3% so the certifier has something to certify.

## Recommendation: synthesize vs. use real

Use real data for: (1) a held-out realism eval set (MoneyData, 6,543 labeled rows; do not train on it as the only source), (2) merchant/alias lists (NSI), (3) descriptor FORMAT templates (DoDataThings 8 formats), (4) taxonomy (Plaid PFCv2), (5) amount/time shape and base rates (TabFormer/PaySim).

Synthesize with a frontier model for: SaaS/B2B vendors (200-500), invoice JSON with line items tied to specific bank lines, draft_note text, rule-injected anomaly cases, and human-review edits (mission 4 needs a reviewer-change signal; no public dataset exists, simulate with a perturbation policy).

Pipeline: seed ledger in code (NSI merchants x format templates x amount distributions x vendor recurrence) = free and byte-reproducible with a seed (matches the replay requirement); LLM labels = the actual agent steps.

My cost estimates (arithmetic, assumptions stated; not measured):

- 2,000 invoice JSONs, ~350 output tokens each: 0.7M out. Haiku about $0.35; Sonnet about $7.

## Blockers / plan changes

- Kaggle login: PaySim original (ealaxi/paysim1), ULB creditcardfraud, IEEE-CIS, kartik2112 Sparkov set, IBM AML original. Use the no-login mirrors above; license on mirrors is the uploader's tag, not verified against upstream.
- mitulshah (4.5M rows) requires HF login (gated: auto). Avoid; DoDataThings + MoneyData cover the need.
- TabFormer merchants are hashed ints: it cannot back `categorize_transaction` text experiments, only amount/MCC/fraud distributions. Box mirror 404 from curl; use the GitHub media URL.
- No open merchant-normalization or invoice<->transaction matching dataset exists. Plan: generate (canonical merchant -> descriptor variants -> invoice) triples ourselves; ground truth then comes free.
- MoneyData is one person's account with 909 distinct descriptors: fine as a test set, too small/repetitive to train a student. DoDataThings is class-balanced and synthetic: students trained only on it will look better than reality; certification must run on a skewed, held-out mix (MoneyData-style).
- Label-space choice affects "~12 labels": propose a 12-label subset of Plaid PFCv2 primaries or DoDataThings labels; do not mix schemas.
- Synthetic-eval warning: DoDataThings' own companion model reports 99.9% on synthetic validation but 96.1% of ~2,000 real transactions at 0.90+ confidence (model card summary via search, not independently verified). Expect the same optimism in our certifier if the test set is templated.
- Human-review deferral (mission 4) has no public data; must simulate reviewer edits.
- Cost is not a blocker: whole data build is under about $20 even on Sonnet-class models.
