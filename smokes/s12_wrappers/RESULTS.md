# S12: the four wrappers + record-and-replay (mission 6, revised)

`dreaming_wrap.py` is the whole library: 316 lines (291 non-blank), stdlib plus `openai` types; `uagents_core` is imported lazily. It was 209 lines before the review fixes (see Revision for where the 107 lines went). Tests are small scripts, all green, stdout in `log.txt`. Versions: Python 3.12.12, openai 3.33.0, langgraph 1.2.16, langchain-openai 1.7.2, uagents 0.26.1, uagents-core 0.4.12. The whole suite runs in about 75 s.

Shown by the tests:
- **T1 LangGraph.** Both nodes log under ONE run id with sites `categorize` (tagged by header) and `draft_note` (tagged by `call_site()`); the run row says `calls=2`. Copying node A's answer into `predictors` gives `predicted=true` for A with zero network calls and B live. Replay of the all-live run and of the run with a predicted row both make 0 network calls and return identical outputs. Changing node B's prompt gives `Divergence` at row 2: expected and actual are both `draft_note`, with different request hashes. A handler that stops early is also a divergence (row 2, actual None). `recertify` re-ran the predicted call live on its logged prompt and got the same text. The async variant (`AsyncOpenAI` + async nodes + `ainvoke`) now has the full set: record, predictor, replay, divergence at row 2 (zero network calls) and `arecertify`.
- **T1b context and streams.** The wrapped OpenAI client was run from three parallel LangGraph nodes (worker threads, mock transport): every row carries the run id and indices 1..3. `run_boundary(app.stream)` and `run_boundary(app.astream)` keep the run open until the last chunk (run row written after it, `calls` correct, rows have the run id), and a stream replays with zero requests.
- **T2 uAgents.** `ctx.send_and_receive` exists with signature `(destination, message, response_type, sync=False, timeout=30) -> tuple[Model | None, MsgStatus]`; `ctx.send` is `(destination, message, timeout=30)`. A real requester handler calls the responder over HTTP between two processes. The call is logged as site `<responder address>|VendorLookup`, call 1 of the requester's run, and the reply `ctx.send(sender, Answer)` is call 2 (effect). A learned predictor made the second `globex` ask skip the send: the responder log shows no second hit. After killing the responder, a known vendor was still answered (predicted), and an unknown vendor was answered by the registered fallback after 2.05 to 2.08 s over four runs (`error=RuntimeError('Message delivery failed')`, `fallback=true`). The predicted `globex` row was re-executed against the live responder from the driver agent's ctx (`arecertify`): same answer. Each of the 5 runs replays through the real decorated handler with a fake ctx, with identical replies.
- **T2b replay edge cases.** A soft failure with no fallback (`(None, MsgStatus(FAILED, 'connection refused'))`) replays as the same tuple, so `if info is None` takes the same branch. `ctx.send` and `ctx.send_and_receive` with keyword arguments (`destination=..., message=...`, mixed forms) run and are logged.
- **T2c chat protocol (new).** `Protocol(spec=chat_protocol_spec)` with `@proto.on_message(ChatMessage)` under `@run_boundary`, between three real processes (responder, chat agent, driver). One chat message = one run id holding four rows: the `ChatAcknowledgement` effect, the `send_and_receive` lookup, the `AsyncOpenAI` model call (site `reply`) and the `ChatMessage` reply effect. The second identical chat is answered with the send AND the model call skipped (`predicted=true` on both, responder and model HTTP counters unchanged). With the responder killed, a known vendor is still answered and an unknown one takes the fallback and a live model call. Recertify of the two predicted rows against the live responder and the live model: both same. All four runs replay in a fresh process through the real handler with the real wrapped client; a negative control (`embeddings.create` on that client in replay mode) is refused before any request.
- **T3 tool.** Predictor conf 0.99 and 0.97 against cutoff 0.9 skip the body. Conf 0.5 runs the body and still logs `pred` next to the real return (free calibration data). An exception returns the fallback (a value, or a callable that receives the tool's args) and logs the error; with no fallback it re-raises and logs. A crashing predictor is a miss. The async variant matches. Replay executes no tool body and returns the same results, fallback included. A changed arg diverges at row 2. `recertify` re-ran the predicted tool rows (sync and async) on their logged args: same; a deliberately wrong predictor (`net99` vs real `net30`) was caught (`same=False`).
- **T0 offline unit checks** (httpx MockTransport, no cost). Untagged calls are logged under `sys:<sha1(system prompt)[:12]>`; header beats `call_site()`. A tool-call response (content None) round-trips through replay as a real `ChatCompletion`. API errors are logged and re-raised, and the run row carries the error. Nested boundaries join the outer run. 21 concurrent calls from copied contexts get unique, gapless indices. Streaming is refused in replay. New: `with_options()` and `copy()` calls are logged (3 of 3) and replay with 0 extra requests; an embeddings request in replay raises `ReplayLeak` (also with the SDK's default retries, and also when the handler swallows it: the boundary raises at exit); tool returns of tuple, set, frozenset, bytes, non-string-key dict, dataclass, pydantic model, datetime, date and UUID replay with the same type; a tool that raised `TimeoutError("vendor db down", 7)` replays as `TimeoutError` with the same args; an openai `InternalServerError` replays as that class with `status_code == 500`; a return value the codec cannot reproduce (`object()`) stops the replay with a divergence instead of returning a string.

## Gotchas

1. **ContextVar propagation (LangGraph).** On Python 3.12 / langgraph 1.2.16 nothing was lost, so no library fix was needed. A lone sync node runs inline in the caller's thread. Parallel sync nodes run in `ThreadPoolExecutor` workers and keep the run id (shown for both the `@tool` wrapper and the OpenAI wrapper). Sync nodes under `ainvoke` run in an executor and keep it, and so do async nodes, `asyncio.to_thread` and `create_task`. The run id IS lost in two cases: a user-spawned `threading.Thread`, and a bare `loop.run_in_executor`. Rows from those calls land with `run_id=None`. The fix is `contextvars.copy_context().run` taken in the submitting thread (a copy taken inside the worker has no run id). The run state is a dict held by reference, so copied contexts share one call counter. Not tested: Python below 3.11, where LangGraph's docs say async nodes need explicit context handling.
2. **Building a `ChatCompletion`.** `ChatCompletion.model_validate` needs id, object, created, model, choices and usage. We fill usage with zeros and a fake id, and keep `n=1` only. Replay rebuilds from the logged `choice` dict (`model_dump(exclude_none=True)`), so `tool_calls` survive. Predictors are plain text, so a tool-call turn can never become a predictor answer (its `text` is None).
3. **Async detection.** `AsyncCompletions.create` is NOT `iscoroutinefunction` (it is wrapped by `required_args`). `_async()` uses `inspect.unwrap` first; without it the async client logs a coroutine object. Related: the SDK's own `create` has a `__wrapped__` (the unbound function), so recertify finds the original through our own `_orig` attribute, not `__wrapped__`.
4. **`with_raw_response` (langchain_openai).** `ChatOpenAI` calls `client.with_raw_response.create`, which is a `cached_property` that captures `create` at first access, so wrap before first use. It routes through the patched `create` with an `X-Stainless-Raw-Response` header, and the real return is a `LegacyAPIResponse`. The wrapper logs `.parse()` and returns the original; for served calls it returns a small `Raw` shim (`.parse()`, `.headers`). The async raw path (`ainvoke` on `ChatOpenAI`) passes through unlogged. `ChatOpenAI` structured output uses `.parse`, also unwrapped.
5. **Streaming.** Model-token streaming (`stream=True`) is not supported: it passes through unlogged in record mode and raises in replay. Graph streaming (LangGraph `stream` / `astream`) is a different thing and works through `run_boundary` (generator support).
6. **Temperature 0 is not byte-deterministic on gpt-5.4-nano via OpenRouter.** The same `draft_note` prompt gave a different note in every live run of T1. Replay serves the log, so it is exact. A fresh live call matched on one-word and one-line answers (`recertify` passed in T1 and T2c), but "re-execution equals log" will not hold for free text on this model. That is the premise of the certificate gate, not a wrapper bug. T2c also saw the model clip its own reply at `max_tokens=60` once, so tests do not assert on model text beyond what the rows prove.
7. **uAgents.**
   - `send_and_receive` returns `(None, MsgStatus)` on failure and on timeout; it does not raise. The wrapper treats `None` as a soft failure: fallback if registered, otherwise pass-through with the error logged; replay returns the same tuple with the logged status. An outage took 2.05 to 2.08 s to detect (dispenser retries) even with `timeout=4`.
   - Handlers must be `async def`. Order is `@agent.on_message(...)` (or `@proto.on_message(...)`) outermost, then `@run_boundary`; `functools.wraps` kept the signature and uAgents accepted it.
   - The ctx object is per message, so the wrapper must run per handler invocation. `run_boundary` therefore wraps any positional arg that has `send_and_receive` (setting attributes on the ctx works). The wrapper binds the real signature, so keyword and positional calls both work.
   - uAgents `Model` is pydantic v1: `model_dump()` takes no `mode` argument. Bodies are serialized with `json.loads(m.model_dump_json())`, which works on v1 and v2.
   - Message models need identical class name and fields in both processes, because the type is matched by schema digest. Use a shared module. Per source, a `response_type` that does not include the received type raises KeyError inside uAgents.
   - Chat protocol: `agent.include(proto, publish_manifest=False)` (True would POST to Agentverse). `ChatMessage` / `ChatAcknowledgement` build `msg_id` and `timestamp` themselves, so their bodies differ on every run. That is why effects are checked in replay by destination and type only (see Hashing); a body hash would diverge on the very first row, the ack.
   - Ports: one per agent (8101 to 8104), or one shared port in a Bureau. `RulesBasedResolver` gives static address -> endpoint maps, so no Almanac lookup. Call sites embed the destination address, which is stable only if agents use `seed=`.
   - Registration was skipped with a no-op `AgentRegistrationPolicy`. `Agent._update_agent_status` also POSTs to the Almanac API at startup and shutdown (per source), so I patched it (private API) to keep the smoke fully local. No Agentverse or ASI:One calls were made; OpenRouter stands in for ASI:One's OpenAI-compatible endpoint.
8. **Hashing.** The openai row hash is sha256 of the messages JSON only (as in s10's proxy), so changing tools, model or temperature alone does not diverge a replay. Tool and a2a hashes cover the packed args/kwargs and the message body; an arg whose only representation is a `repr` with a memory address becomes a `$lossy` string and breaks replay (loudly). Effects (`ctx.send`) are hashed by destination and message type only.
9. **Replay ordering.** Rows are numbered by call start order within the run, and replay is strict about it. A 3-way LangGraph fan-out with instant calls replayed with 0 divergences in 40 tries; the same fan-out with a random 0 to 15 ms delay before each branch's call gave 37 spurious divergences in 40. So parallel branches replay only when their start order is deterministic. The upgrade is matching by (site, hash) among unconsumed rows; not done because it would hide order changes.
10. **Process-global Recorder.** The last `Recorder(...)` wins and is read at call time, so a client can be wrapped before the recorder exists. Two recorders in one process are not supported.
11. **Replay and live HTTP.** Wrapping patches one client instance. `client.with_options(...)` and `client.copy(...)` return NEW clients, so both are re-wrapped. Every wrapped client's httpx `send` is also guarded: in replay mode any request that is not a served wrapped call (Responses API, embeddings, `parse`, streams) raises `ReplayLeak`, and the run boundary raises it again at exit if the handler swallowed it. The guard is on the httpx client that the SDK shares between copies, so it cannot be bypassed by a copy.

## Where the text was ambiguous (simplest reading taken)

- "Certified cutoff" is a confidence number per call site supplied by the caller (`cutoffs={site: x}`); the default is infinity (never skip). There are no certificate objects.
- One registry keyed by call site: `predictors[site]` is a `{hash: text}` dict for model calls and a callable `(*args) -> (value, confidence)` for tools and a2a. `fallbacks[site]` is a value or a callable. A `tool(..., fallback=)` argument overrides the registry.
- Replay row numbers are 1-based (the Nth wrapped call). Replay reuses the logged run id and writes no rows. Effects (`ctx.send`) are replayed as skipped sends but still consume a row, so order, destination and type are checked (not the body).
- Replay of a failure raises the logged exception class again (rebuilt without running `__init__`, with its JSON-safe attributes), or returns the logged soft-failure value; it never substitutes a different error type.
- `speculate_next` is a logged hint only. A nested `run_boundary` joins the open run. Run ids are `uuid4().hex[:8]`.
- No fallback for model calls (the spec gives fallbacks to tools and a2a only). `recertify` re-executes every predicted openai (sync or async client), tool and a2a row; it must run in record mode.

## The change per framework

- **OpenAI-compatible client (any framework):** `client = wrap_openai(OpenAI(...))` (or `AsyncOpenAI`), plus once at startup `Recorder("record", "traces.jsonl", predictors=..., cutoffs=...)`. Tag a site with `extra_headers={"X-Dreaming-Call-Site": "name"}` or `with call_site("name"):`.
- **LangGraph:** `invoke = run_boundary(app.invoke)` (or `ainvoke`, `stream`, `astream`), plus the client line above. With `ChatOpenAI`: `wrap_openai(llm.root_client)` and a `call_site()` around the node.
- **uAgents:** add `@run_boundary` under `@agent.on_message(...)` or `@proto.on_message(ChatMessage)`. The ctx is wrapped automatically, so `ctx.send_and_receive` and `ctx.send` are covered with no other edit. Model client: `wrap_openai(AsyncOpenAI(base_url=<ASI:One>))`. Tools: `@tool("name")`.
- **Tools:** `@tool("name", fallback=..., speculate_next="next_step")`.

## NOT covered

Responses API (`client.responses.create`), the OpenAI Agents SDK, MCP, model-token streaming (`stream=True`), async `ChatOpenAI` raw responses, `n>1`, `chat.completions.parse` / structured outputs, embeddings (these go through the client unlogged in record mode and fail loudly in replay mode), Bureau (separate processes only), hosted Agentverse sandbox (proxy path, s10/s11), parallel-branch replay when branch start order varies (37 of 40 replays diverged), Python below 3.11, a model-call fallback, certificate / weights / environment hashes in the rows, and the SDK's own retries (one row per `create`). The type-preserving codec covers JSON natives, tuple, set, frozenset, bytes, non-string-key dict, dataclass, pydantic model, datetime, date and UUID; anything else (namedtuple, Decimal, Enum, arbitrary classes) is logged as a string and refused in replay. Replayed exceptions keep only JSON-safe attributes (`status_code`, `message`), not `response` objects. A real ASI:One endpoint and a real Agentverse mailbox were not used.

## Revision

A review of the first version found three material problems and several smaller ones. Each fix has a test that fails on the old library (the with_options case was re-run against the old file: 1 of 3 calls logged).

**Material**
1. **Replay went live through `with_options()` / `copy()`.** `wrap_openai` patched one client instance and those methods return new unwrapped clients: 1 of 3 calls was logged, and in replay 2 requests left the process with no divergence. Fix: both methods are re-wrapped (so their calls are logged and served), and each client's httpx `send` is guarded so that in replay mode any other request (Responses API, embeddings, `parse`, streaming) raises `ReplayLeak`. This also turns the earlier "not covered, goes live in replay" list into loud failures. Tests: t0 (g, h), t2c negative control with the real client.
2. **Replay did not reproduce failure rows or types.** (a) The a2a soft failure with no fallback now replays as `(None, MsgStatus)` with the logged status, not a `RuntimeError`; the full status is logged. (b) A raised exception is logged with its class, args and JSON-safe attributes and rebuilt on replay, so `except TimeoutError` and `except openai.InternalServerError` still match. (c) Tool and a2a returns use a small type-preserving codec instead of `default=str`: tuples, sets, bytes, dataclasses, pydantic models, datetimes and UUIDs replay with the same type, and a value the codec cannot reproduce stops the replay with a divergence instead of silently becoming a string. The "replays exactly" claim now holds for those types and for failures; it does not hold for exotic types (listed above), which fail loudly. Tests: t0 (i), t2b.
3. **`ctx.send` crashed on keyword arguments.** `mk_send` indexed `a[0]`, `a[1]`. It now binds the real signature like `send_and_receive` does. Test: t2b (positional, keyword and mixed forms, record and replay).

**Smaller**
- `run_boundary` on a generator entry point closed the run before the first chunk. Sync and async generator entry points now hold the run open until the stream ends; a closed run left behind in another context is ignored. Tests: t1b. The NOT-covered list now separates model-token streaming (still unsupported) from LangGraph `stream` / `astream` (supported).
- Recertify was sync-openai only while the table said yes everywhere. It now covers `AsyncOpenAI` (`arecertify`), tool rows (through a registry of the undecorated functions) and a2a rows (through a live ctx), as the mission text asks ("re-execute every prediction"). Tests: t1 (sync and async), t3 (including a wrong predictor, caught), t2 and t2c (a2a and model against live processes).
- The async LangGraph variant only had record, predictor and replay checks. Divergence (row 2, zero network) and recertify were added to t1, so the "same checks" statement is now true.
- The chat-protocol path was untested. t2c uses `Protocol(spec=chat_protocol_spec)` and `ChatMessage` / `ChatAcknowledgement`. It found one real issue: the ack carries `datetime.now()` and a fresh `msg_id`, so hashing effect bodies made every chat replay diverge at row 1. Effects are now hashed by destination and type.
- A uAgent handler combining the model wrapper and `run_boundary` is now shown (t2c: `AsyncOpenAI` plus `send_and_receive` plus two effects under one run id, predicted, outage, replay).
- The OpenAI wrapper itself now runs on LangGraph worker threads (t1b, three parallel nodes, mock transport): run id on every row.
- Parallel-branch replay ordering is now measured, not just disclosed: stable when start order is stable (0 of 40), unstable when it is not (37 of 40). Kept strict, as specified.
- The 2.07 s outage figure was run-to-run noise; the text now says 2.05 to 2.08 s over four runs.
- Cost: `cost_s12.json` now counts T1 (including the recertify calls, which write no rows), T1c and T2c; the COSTS.md estimate was refreshed.
- Left as is: the openai hash covers messages only (as in s10 and the spec wording); rows carry no certificate / weights / environment hashes (S12 does not require them).

**Cost of the fixes.** The library grew from 209 to 316 lines: the type-preserving codec and exception rebuild are about 50 lines, `arecertify` for tool, a2a and async about 23, the replay transport guard about 9, the rest (generator boundary, leak handling, clone re-wrapping, signature binding) about 25. The "tiny library, under about 200 lines" target is missed; the core of the four wrappers plus record and replay is still about 230 lines and the rest is replay fidelity and recertify. If size matters more than fidelity, the codec is the part to cut: it can shrink to JSON-only with a loud refusal for anything else.
