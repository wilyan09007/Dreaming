# S27 hybrid embedder swap and memory heads on the new-step tasks (CPU, $0)

## In plain words

Two cheap questions from the hybrid-architecture note (`smokes/research/hybrid-architectures-transfer.md`, bottom line items 3, 5, 6). First: if the frozen 33M-parameter encoder (bge-small) is swapped for a hybrid convolution-plus-attention embedder (LiquidAI LFM2.5-Embedding-350M, 354M parameters), does the same logistic-regression (LR) head answer more traffic within the 5% error budget at 1, 3 or 10 labelled rows per label? No: it is slightly worse at k=1 and k=3 and equal at k=10, at 30 times the encoding time. The attention control of intermediate size (bge-base, 109M) is the one that helps (+0.14 certified coverage at k=3, paired s.e. 0.045). Second: do "memory" heads on the frozen bge-small vectors (a delta-rule online least-squares classifier, as in the test-time-training / Titans view, and a Hopfield softmax read) beat LR? No: all of them tie or trail LR, as the note predicted. The gap from LR reaches -0.12 in certified coverage (delta rule, k=3) and -0.04 to -0.09 at k=10, and is within about 1 to 2 standard errors in most cells, so "tie or slightly worse" is the honest summary. The bar here is plain LR only; the LLM-written-examples prior (S17's best warm start) is not included because its cache is not in this clone.

## Setup

- **Protocol:** the S23/S25 protocol (`smokes/s25_exotic/lib.py` `build`/`draw`/`score`, re-implemented text-only in `run.py` so the encoder can change): 5 tasks = CLINC150 `travel` and `work` (15 labels each) and three disjoint 12-label Banking77 sub-tasks (`default_rng(0).permutation(77)`, blocks 0:12, 12:24, 24:36). Per task 300 train rows set aside as calibration (`default_rng(100+i)`), the rest is the pool, the official test rows are the evaluation set (450 / 450 / 480 / 480 / 479 rows). k = 1, 3, 10 real rows per label, 3 draws (seeds 0-2), identical rows for every arm so arms are paired.
- **Metrics:** test accuracy; certified coverage at a 5% budget via `common.certify` (fixed grid 40, delta 0.05) fitted on the 300 calibration rows with confidence = top-2 gap of the arm's class scores, cutoff applied to the test rows; realized error above the cutoff. "+-" in the main table is the s.d. over the 3 draws of the task-averaged value; paired differences use the 15 (task, draw) cells with the standard error over cells.
- **Baseline:** frozen BAAI/bge-small-en-v1.5 + LogisticRegression(C=10).
- **Arm 0, embedder swap (same LR head):** (a) LiquidAI/LFM2.5-Embedding-350M exists on the Hub (sentence-transformers + custom code, CLS pooling, 1024-d, 354M parameters, hybrid short-convolution + attention, bidirectional). It does not run unmodified with transformers 5.x: the repository's `_noncausal_shortconv_forward` does not accept the `seq_idx` keyword the library now passes. I ran a local copy with one change (`**_ignored` added to that signature, no change to the maths). (b) bge-base-en-v1.5 (109M, 768-d) as the attention control. Embeddings were taken without any query/instruction prefix, max length 128, unit-normalised, cached as `.npy` under `smokes/.cache` (10,203 texts per model).
- **Arm B, memory heads on frozen bge-small:** (i) delta rule: `W <- W + lr (onehot - W x) x^T` over the k x K rows in shuffled order, bias via a constant feature, W initialised to 0; lr in {0.03, 0.1, 0.3, 1.0} x epochs in {1, 3, 10, 30} picked per cell on calibration accuracy (then squared error); confidence = top-2 gap of the raw scores. Also run: a regularised closed-form least-squares head (ridge, lambda in {1e-3 ... 10} on calibration, mostly 0.1 to 10), which approximates the delta rule's converged end only as lambda goes to 0. The delta-rule grid sits on its edges (30 epochs and lr 0.03 or 0.1 are picked most); lr=1.0 is at the stability edge and was never chosen; ridge covers the converged end. (ii) Hopfield read: `softmax(beta cos) @ onehot` over the stored rows, beta from S24's grid 5 to 640 picked on calibration NLL (S24 arms 1b). (iii) plain LR reference = the baseline row.
- **Not included:** the LLM-written-examples prior (S17/S24 arm 1c); its cache is not in this clone. Numbers from S17/S24 are context only.
- **Cost:** no API calls, $0. Encoding times were measured on 4 shared CPU cores with other jobs running (load average about 5), so absolute ms per text are inflated for all three models.

## Caveats

- The LFM2.5 result depends on a one-line local patch to make its custom code run under transformers 5.x, no query/instruction prefix, CLS pooling as shipped, max length 128 and fp32 on CPU. An instruction prefix or a different pooling could change it; it was not tried. Vendor-reported retrieval scores were not checked.
- A hybrid embedder at one size (350M) against one control (bge-base, 109M) is not a controlled architecture comparison: they differ in size, data, dimensionality (1024 vs 768 vs 384) and training recipe. The bge-base gain is as likely to be dimension/size as "attention". No SSM-only embedder was run.
- Memory-head hyper-parameters (beta, learning rate, epochs, lambda) are selected on the same 300 calibration rows that fit the certificate, as in S24; this favours the memory heads slightly, so their deficit is not an artefact of under-tuning but selection optimism cannot be excluded. The delta rule's confidence is the gap of unnormalised scores, not probabilities, which may cost it coverage relative to LR; a softmax/temperature variant was not run.
- Only 3 draws and 15 cells per arm and k: coverage s.d. over draws is 0.03 to 0.13, and k=1 coverage is zero in most cells, so k=1 coverage differences are not distinguishable from noise. The baseline differs from S24's digits only because of the split/pool differences described above.
- Fit and encoding times were measured under CPU contention; use ratios, not absolute values.

## Verdict

Prior from the research note confirmed: on a frozen-encoder plus linear-head student at 12 to 15 labels, the hybrid LFM2.5-Embedding-350M does not beat bge-small + LR (paired coverage -0.06 / -0.05 / 0.00 at k=1/3/10, accuracy -0.018 / -0.009 / -0.001, none beyond about 2 s.e.; k=3 accuracy -0.009 is 1.9 s.e., coverage differences 0.9 / 0.9 / 0.0 s.e.) and costs about 30 times the encoding time; a plain attention embedder of 109M parameters (bge-base) does help (+0.14 coverage at k=3, +0.04 at k=10, +0.02 accuracy at k=1). The delta-rule and Hopfield memory heads tie or trail LR (coverage differences -0.12 to +0.03 at k=3, -0.04 to -0.09 at k=10; accuracy 0.4 to 1.8 points lower, about 2 to 4 s.e. for the delta-rule and Hopfield rows at k=3), and the regularised least-squares head (ridge) is no better than LR (-0.060 +- 0.029 coverage at k=10, about 2.1 s.e.). Nothing here argues for replacing the small encoder with a hybrid or for a Titans-style memory head; the open bar remains S17's LR on LLM-written rows, which this study did not re-run.
