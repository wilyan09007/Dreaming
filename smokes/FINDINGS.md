## Headline answers (preliminary, updated as smokes land)

**How long does training take, what does it cost?**
- **Minutes, cents.** Best student per call site is a fine-tuned 33M encoder (bge-small) + linear head: 17 s / 43 s / 131 s on an RTX 4090 for 770 / 3,080 / 9,993 rows, reaching 82.5% / 92.0% / 94.1% on Banking77 (77 labels) with 59% / 89% / 94% certified coverage at a 5% budget (S8 v2). The CPU-only frozen-embedding + logistic-regression student is within 1–2 points (82% / 91% / 93.3%) and trains in seconds to 3 minutes on the laptop (S1). A 0.5B LoRA decoder costs 3–7× the time and never wins. Extrapolation: 100k rows ≈ 20 min, 1M rows ≈ 3 h of a $0.34/h GPU per retrain. A shared-workflow student pretrained on sibling steps makes a new step certifiable from ~45 rows instead of ~150 (S8 phase B). A day-zero student from the schema alone costs $0.005 of LLM-written examples (S2b).
- The binding cost is **teacher labels, not compute**. A certificate at a 5% error budget with 95% confidence needs about 200 calibration rows per call site to certify most of a good student's coverage and 500 to saturate (S1 with the grid certificate: 100 rows certify nothing, 200 rows 70–93%, 500 rows 85–95%); weaker students and human-correction certificates need 500–1,500 (S3), and ~1,500–2,000 rows approach the ideal cutoff. Teacher labels cost $0.04–0.37 per 1,000 on cheap tiers and $1.7–1.8 on Sonnet/GPT-5.4-class models (S5, S13), so even 2,000 rows × 10 call sites is under $40 with a frontier teacher and under $2 with Haiku-5.5. Routers and pruners need the same calibration volume per call site.
- Campaign spend so far: $0.50 RunPod (three pods, balance $19.99 → $19.50), $7.30 OpenRouter (key usage; the per-smoke ledger in `COSTS.md` undercounts by ~$1.3 of probing), ~$0.03 ASI:One. The $100 cap was never at risk.

**Do the data and benchmarks exist?**
- Typed classification steps: yes, free, no login (Banking77, CLINC150, MASSIVE, TREC). Real human text with real label confusion — ideal for certification curves.
- Bookkeeping-shaped data: **no public real raw-descriptor dataset without a login.** Best no-login inputs: `DoDataThings/us-bank-transaction-categories-v2` (68k synthetic descriptors in 8 bank formats, MIT) + MoneyData (8k real UK rows, CC-BY-4.0, only 909 distinct descriptors) + OSM name-suggestion-index (17.8k brands with aliases) for vendor ground truth. Nothing links transactions, vendors, invoices and anomalies: **the demo ledger must be synthesized** (seeded generator; teacher re-labels; hold out merchants, not rows). Est. <$1 (Haiku) to ~$15 (Sonnet) for a 20k-row ledger + 2k invoices.
- Tool returns with real tools: tau2-bench `banking_knowledge` domain (MIT; 17-table bank DB, deterministic Python tools, 266 bank transactions with raw descriptions) and tau-bench historical trajectories (free logged tool calls/returns). Large trace corpora (Nemotron-Agentic, ToolBench) have LLM-simulated returns — plumbing only.
- Routing: RouterBench (11 models, 2023 vintage) and LLMRouterBench (33 models incl. GPT-5 / Qwen3 thinking vs instruct, 1.28 GB, no gate) give free offline cheap-vs-expensive agreement; neither has bookkeeping-style typed steps, so S5 also runs a live paired smoke.
- Human corrections (mission 4): no bookkeeping reviewer-edit data exists. Closest real sets: AlleNoise (502k texts, 74k expert-corrected), ChaosNLI, labelerrors.com. S3 simulates the reviewer with gold labels.
- Context pruning: no public pruner targets typed agent prompts. Closest recipe: AGORA (RoBERTa scorer on counterfactual "output changed when span removed" labels, MIT code). LLMLingua-2 is a weak, query-unaware baseline on structured text. S6 builds our own on HotpotQA.

## Plan changes the research forces
1. **Budget teacher calls for certification rows, not training rows.** Define the reference label as the teacher's temperature-0 output and measure its self-agreement first (S13); budgets below the teacher's own flip rate are not measurable.
2. **Student ladder, CPU first:** frozen embedding + LR → SetFit → fine-tuned encoder → LoRA decoder. Move up only if certified coverage improves. The hypernetwork is a head-only CPU experiment, dropped if it does not beat the baselines.
3. **Synthesize the bookkeeping world** (seeded generator, deterministic ids and a virtual clock so byte-replay works), hold out merchants for the certificate split, use MoneyData only as a skewed realism eval.
4. **Fix the logging/replay contract before missions:** raw request/response bytes + state_hash per tool call; force Chat Completions in every framework or proxy `/v1/responses` too; pinned execution profile + startup canary.
5. **Retarget missions 3 and 7:** caches keyed on state for read tools, shadow-only for writes, speculate the next *LLM* step (seconds) rather than ms tools; rollout = chained certified predictors with per-step verification, evaluated on tau-bench/tau2 at $0.
6. **RunPod API deprecation:** REST v1 retires 2026-11-15 and GraphQL "early 2027". Our launcher uses GraphQL (works today); port to REST v2 (`api.runpod.io/v2/pods`) before then.
7. **The certificate search must be a fixed grid, not a binary search.** S4's critic found that the SGR-style binary search in `common.certify` is path dependent: the Clopper-Pearson bound is U-shaped in coverage, so a failed probe at half coverage says nothing about other coverages, and the search reported "nothing certifiable" where a feasible cutoff existed (minimal case in `common.py`'s self-check). Fixed in `common.py`: evaluate 40 fixed coverage levels with δ/40 each (union bound) and keep the largest that passes; the old search is kept as `certify_sgr`. The bug was conservative (it under-certified, never over-certified), so no realized-error claim above is wrong, but coverage figures from S1/S3/S5/S8 that used the old search are lower bounds; S1, S3 and S5 are being re-run with the fixed certifier, S4 and S9 already use a grid.
8. **Prompt-only routers are no better than random mixing.** S5's revision added the obvious baseline (route to the cheap model with probability p): on RouterBench the embedding router's cost saving at ≤0.5–5-point accuracy loss is at or below that line; the savings that exist come from cost concentration (a few expensive prompts), not from predicting which prompt the cheap model gets right. Mission 1 should be built as per-call-site routing with measured match rates and per-input disagreement classifiers only where they beat random mixing.

## Smoke results (details in each folder)
- **S1 student + certificate** — done, re-run with the grid certificate (plan change 7; earlier numbers kept in `RESULTS_sgr.md`). Banking77: 77 rows 60%, 385 rows 69% (17% coverage certified at 5%), 770 rows 82% (57% coverage, realized 3.2%), 3080 rows 91% (85%), 9993 rows 93.3% (88% coverage at 1.9% realized; a 2% budget → 48% coverage at 0.4%). CLINC150: 1500 rows 91% (80%), 3000 rows 94% (92%), full 96% (98% coverage; 2% budget → 88%). **Calibration size: 100 rows certify nothing; 200 rows already certify 70% (Banking77) / 93% (CLINC) coverage at a 5% budget; 500 rows ≈ full coverage.** Top-2 gap and max-prob give identical coverage. LR fit on 10k rows × 77 classes takes ~1 min CPU uncontended; embedding 13k texts ≈ 1 min.
- **S7 determinism (CPU)** — done. 1000 batch-1 calls from 8 concurrent threads → **1 distinct** embedding. But: the same text inside random batches of size 1–8 (dynamic padding) → **8 distinct** byte-strings (max abs diff 9e-8); changing `torch.set_num_threads` (1/2/4 vs 8) changes bytes too. Downstream LR argmax never changed and the top-2 gap moved by 6e-7, yet 6 distinct probability byte-strings. Conclusion: byte-identity on CPU requires fixed input shape (batch 1 or fixed padding) **and** a pinned thread count, both of which belong in the environment hash; quantize confidence before hashing. Matches the research (CPU/MKL is not batch-invariant either).
- **S3 review deferral** — done (with an independent critique pass that corrected three over-claims). Reviewer = gold label; student = 770-row LR (82% acc, 18% of outputs "changed") and 3080-row LR (91%, 8.6%). Ranking by the raw top-2 gap already catches 66% of changes when reviewing 20% (random: 20%). A logistic head on student-score features trained on 1000 corrections beats the gap for the weak student on every metric (share reviewed to catch 80%: 28.5% → 24.2%; AP 0.58 → 0.72; caught at 10% review 34% → 41%), helps only at the top of the queue for the strong student, and a naive embedding-feature head is worse than the score-only head. Head beats gap on AP already at 300 corrections for the weak student. Certificate against corrections holds in every split (max realized change rate 3.0% under a 5% budget), but **calibration size dominates**: weak student at 5% budget certifies 0 / 35% / 54% / 57% auto-pass coverage at 250 / 500 / 1000 / 1500 calibration rows, and tree/embedding heads produce infeasible certificates in 12 of 20 draws at 500 rows (an early error in the top rows makes the bound unsatisfiable). Recommendation: start on the raw gap, switch to the score-feature head after a few hundred corrections, plan ≥1000 reviewer-labelled rows per site for a 5% certificate.
- **S11 ASI:One / Agentverse** — done: **works end to end, fully scriptable from the two keys, no UI click, ~$0.03.** Hosted path: REST create → secret → code upload (`code` must be a JSON-encoded string, the docs' array shape returns 422) → start → logs → stop, all HTTP 200; `requests`/`openai` are on the hosted import whitelist and the hosted agent called ASI:One. Local path: (a) cloudflared quick tunnel + `register_chat_agent` works (Almanac type `proxy`); (b) **mailbox connect is programmatic**: the Inspector's "Connect" button only POSTs to the agent's own `http://127.0.0.1:8000/connect` with `{"user_token": <AGENTVERSEKEY>, "agent_type": "mailbox"}`, which returns 200 and needs no tunnel or inbound port. Delivery: ASI:One `asi1-mini` with `planner_mode: true` + `x-session-id` (+ optional `agents: [address]`) routed prompts to our agent and quoted its reply verbatim, including a `certificate: ...` line, in 21–34 s; discovery without an address list found the agent ~3 min after registration, but under confounded conditions (the planner had just been handed the address, and the prompt named the agent), so **cold-start discovery by a vague prompt is untested** and the demo should pass the agent address explicitly; the `@agent` mention is a chat-UI feature, not an API one; no `asi1-agentic` model id exists on this key. Demo plan: runtime + uAgent in one process on the laptop in mailbox mode, chat handler → `asyncio.to_thread(runtime.run_step)` → reply text + certificate line + `EndSessionContent`; keep steps under ~45 s or send an interim message (planner waits 60 s, extended to 240 s once replies start). Estimated 2–3 h to wrap the runtime plus half a day of polish. Two agents (`dreaming-smoke-hosted`, stopped; `dreaming-smoke-local`, inactive) are left registered; seeds in `s11_asi_one/seeds.txt` (secret).
- **S8 GPU student (v1, RTX 4090 $0.34/h)** — phase A done. LoRA r=16 on Qwen2.5-0.5B with a 77-way classification head, 3 epochs, lr 2e-4, bs 32, bf16: 770 rows → 37% (75 steps: under-trained), 3080 rows → 85% in 34 s (63% certified coverage @5%, realized 2.7%), 9993 rows → 91.6% in 110 s (83% coverage). Throughput 272 samples/s, peak 7.6 GB, batch-1 latency 34 ms. **Below the CPU frozen-embedding student (93.3%)**, so per the "first failure is not a verdict" rule a v2 run is in flight with the full student ladder (fine-tuned bge-small encoder, SetFit, tuned LoRA r=32 with separate head LR and a fixed 600-step budget). GPU determinism: 1000 batch-1 passes from 8 CUDA streams → **1 distinct**; same input inside random batches → 12 distinct; random batch sizes with fixed padding length → **8 distinct** (batch size alone changes the kernel path). Recipe confirmed: batch size one with fixed shape, pinned SKU. Phase B (shared vs per-step on a new step) pending.
- **S8 phase B: shared workflow student (2b) vs per-step (2a) on a NEW step** — done. One LoRA trained on 8 CLINC domains (120 labels, step name in the prompt, 88 s), then a held-out domain fine-tuned from the shared LoRA vs from the base model, 60 steps each (7 s per run). Travel: 15 rows 56% vs 55%; **45 rows 84% (shared) vs 60% (base)**, with a 5% certificate feasible only from shared (60% coverage); 150 rows 95% vs 97%; 450 rows 99% vs 97%; 1500 rows 99.3% vs 99.8%. Work: 45 rows **78% vs 65%**; 150 rows 92% vs 91%; 450 rows 96% (93% coverage) vs 95% (84%). So the shared student pays off in the 1–3-rows-per-label regime (a new step certifies with roughly a third of the rows) and is neutral by ~10 rows per label; it never hurt by more than noise.
- **S2 hypernetwork (2d), first pass — failed, instructively.** A 1.35M-param set-transformer that writes linear-classifier weights from label-description embeddings (+k-shot prototypes), meta-trained on 7 CLINC domains (105 labels, 4000 episodes, 13 min CPU): 96% on the domains it saw, but **49% on 3 held-out domains (baseline label-description cosine 71%, 10-shot LR 94%) and 27% on Banking77 (baseline 66%)**. It memorized label identities instead of learning a schema→weights map; 105 training labels is far too few (Text-to-LoRA used 479 tasks). Part 2 (prior from generated weights) also hit a NaN bug at tiny row counts. **Second pass (S2b) — verdict: weight generation loses, data generation wins.** Low-capacity generators (linear residual map, learned metric projection) with early stopping on a validation domain generalize but still do not beat the label-embedding baselines on unseen tasks (k=0 on held-out CLINC: 66–69% vs 71–77%; Banking77: 60–64% vs 66–68%), and a regularized set-transformer stays far behind (44%). The orthogonal idea works: **ask an LLM to write 10 example queries per label from the schema (122 labels, $0.005 on ASI:One `asi1-mini`) and train the ordinary LR student on them.** Day-zero with no trace rows: 87% on held-out CLINC domains (baselines 71–77%), 72.6% on 77-way Banking77 (66–68%), 93% on 12-label Banking77 sub-tasks (88%); with k real rows per label it matches or beats k-shot LR at every k (k=10: 94% / 87% / 96%). It is also the only prior that certifies anything at 0–77 real rows (29% coverage at a 5% budget, realized error ≤1.7%) and gives the best certified coverage at 385–770 rows (51% / 69% vs 31% / 62% from a zero prior). The literature check (`research/day-zero-student.md`) agrees: every embedder's label-description zero-shot plateaus at 64–71% on Banking77, NLI/GLiClass do worse (~56%), synthetic-from-description reaches 70–77% on unseen CLINC in published work, and no paper shows a description-to-weights generator beating label-embedding + prototype baselines with few training tasks (Text-to-LoRA needed 64–479 tasks). **Plan change for mission 2d: "a new step has a student the moment it is declared" is delivered by schema → synthetic examples → student (+ the synthetic student as the prior for the first real rows), not by a hypernetwork.** Stretch "generator writes adapter weights" is dropped.
- **S13 teacher noise floor + latency** — done (5,600 calls, $2.56). The reference label for every certificate is the teacher's own answer, and the teacher is noisy: pairwise disagreement between two identical temperature-0 calls on Banking77 is ~1–3% for claude-sonnet-5.5 (weakly determined, mostly empty-answer artifacts of reasoning that cannot be disabled), 3.5% haiku-5.5 (reasoning off), 4–5% gemini-3.5-flash-lite, 5% qwen3-32b, **11% gpt-5.4-mini**. Flips concentrate on hard prompts (flipping prompts are wrong vs gold 55–73% of the time), majority-of-5 adds ≤1.2 points. **Four of five teachers silently drop `temperature=0` under OpenRouter default routing** (Anthropic and OpenAI endpoints do not support it; `require_parameters` 404s; `seed` unsupported on Anthropic); even honoured temperature 0 is not deterministic. Different endpoints of the same model disagree more with each other (up to 11%) than one endpoint with itself, so **pin the provider and log it in every trace row**. Budget floors: ≈3% sonnet, 6% haiku, 7% gemini-lite, 9% qwen, 15% gpt-5.4-mini. Cost per 1000 labels / p50 latency: sonnet $1.83 / 1.1 s, haiku $0.08 / 0.8 s, gemini-lite $0.18 / 0.6 s, qwen $0.04 / 0.4 s, gpt-5.4-mini $0.37 / 0.8 s. Consequence for the product: the "error budget" the operator sets is disagreement with a noisy reference; budgets below the floor are unmeasurable, and the audit sample should use a pinned reference endpoint.
- **S4 tool return predictor + speculation (synthetic env, mechanics only)** — done. vendor_lookup (return = function of input): char-n-gram TF-IDF + LR certified at a **1% budget** on a calibration slice with the deployment's novelty mix → **67% of test calls skipped at 0.13% realized error** (1 of 792; revised with the grid certifier), 0.5% false-skips on never-seen merchants; pooled over 6 worlds 70% skipped at 0.42% error, with one world at 1.46% against the 1% budget. Nearest-neighbour is also certifiable (37% skipped, 0 errors) once the certifier is fixed (see plan change 7). **Calibrating on known merchants only inflated coverage 30 points and let 4.2% of novel-merchant calls through as confident wrong answers**: the calibration slice must contain the unseen-input rate the deployment will see, and because errors cluster by merchant the iid assumption behind Clopper-Pearson breaks (1 of 6 worlds realized 2.2% against a 1% certificate) → audit sampling and grouped calibration splits are mandatory. lookup_order (hidden state): HGB top-1 0.57 vs Bayes-optimal 0.58, well calibrated; speculation hit rate 0.63 on 71% of calls at τ=0.5, 1.0 on 2.8% at τ=0.9; saves ~17–21% of sequential latency in this env. issue_refund (world-changing): P(error) AUC 0.71 (oracle 0.76), latency MAE better than the median only by 13%; a fallback-first rule at P>0.35 catches 34% of errors at 41% precision. **Outage test:** circuit breaker completes 0%; certified predictor + registered stale snapshot completes **89.3% at 1.68% error** (predictor-answered rows 0.29%, fallback rows 6.3% and tagged for downstream gates).
- **S9 full rollout (synthetic env, mechanics only)** — done. Chaining categorize → vendor → invoice → anomaly predictors from the raw transaction reproduces the whole 4-step real trajectory for **76% of transactions (94% on known vendors, 0% on novel vendors by construction)**, mean matching prefix 3.3 steps. Routing to review on imagined anomaly=yes: precision 0.81 / recall 0.87 against a 0.31 base rate (the same step-4 model on real upstream outputs gets 0.99/0.98, so all loss is upstream). Sequential per-step certification (revised, grid certifier): at a 2% per-step budget 34% of trajectories are fully confident with 1.2% trajectory error; at 3%: 44% confident, 1.5% error; at 5%: 66% confident, 4.5% error; a direct trajectory-level certificate held its budget in every world. **Calls avoided were over-counted 1.7–1.9× in the first version:** `match_invoice` can only be skipped when the imagined output is NONE, so at 3% the rollout avoids 44% of teacher calls but only 23% of tool calls (38% at 5%), and 41% of step latency. Robust across 5 other worlds (72–75% whole-trajectory match; realized trajectory error within the per-step budget in 5 of 6). Confirms the research note: rollout must gate on per-step certified confidence, and novel inputs must stop the imagination at the first uncertain step.
- **S5 tier / thinking router** — done (~$2). Offline on RouterBench (36.5k prompts × 11 models, 2023 vintage): the cheap model is at least as good as GPT-4 on 75% of prompts and an oracle saves 67% of cost, but a prompt-embedding router (AUC 0.63–0.69) saves 3–11% at ≤0.5–2-point accuracy loss, **which is no better than routing a random fraction of prompts to the cheap model** (random mix: 3–12%); the revision withdrew the "router captures 8–11%" reading, and no router passes a 1/2/5% certificate. Live on a 77-label typed step (200 inputs, gpt-5.4 low-reasoning as E1, 87–90% gold): nano / mini / haiku-4.5 / qwen3-32b match E1 on only 77–82% of inputs and lose 10–18 gold points; **thinking on vs off on the same mini model changes 16.5% of answers and is worth +6.7 gold points at 3× cost and 3× latency** (the mission's "3 of 200 changed" example did not hold on this step). Prompt-only disagreement routers are weak (AUC 0.56–0.60) and with 100 calibration rows nothing certifies at any budget ≤20%. Teacher self-disagreement (6% E1, 9% nano/mini; OpenAI endpoints ignore temperature on OpenRouter) caps achievable match at ~0.91–0.94. qwen3's OpenRouter `reasoning` field is ignored by the provider; only the `/no_think` soft switch works. Cost spread is real (E1 $1.72 / 1k calls at 2.3 s; nano $0.10 at 0.8 s) so the lever exists **where the whole call site matches**, i.e. mission 1 works as per-call-site routing with a measured match rate, not per-input routing from the prompt.
- **S6 context pruner (HotpotQA free-text answers; $2.93 after revision)** — done, revised after critique. **Note 4, "can the hybrid network architecture still be used in meta/transfer learning?"** (Read as hybrid SSM/linear-attention + attention models: Qwen3.5 small, Nemotron-H, Falcon-H1, Granite-4.0-H, LFM2, Zamba2, RWKV-7, Titans/TTT.) No published few-shot classification number at ≤1B beats a 33M encoder + linear head, and the one hybrid sentence embedder (LFM2.5-Embedding-350M, 2026-06, vendor-reported) has no MTEB scores yet. What hybrids add is a fixed-size recurrent state that can hold a prefilled support set (constant per-query cost after a snapshot), a latency/replay property rather than label efficiency; pure SSMs are weak at ICL and need attention layers. Titans/TTT memory on frozen embeddings reduces to an online least-squares classifier and a modern Hopfield read, which S24 already measured (≈ LR; the seeded Hopfield is behind LR-on-LLM-rows). Determinism is currently *worse*: vLLM batch-invariant mode rejects Gated DeltaNet models (fix PR open) and Mamba2 hybrids. **Decision (2026-10-17, after round 4, revised the same evening): train every candidate student per call site in parallel and let the certificate pick.** Candidates: the associative memory over the trace store (Hopfield read, seeded with the schema's LLM-written examples; the day-zero tier because it needs no training), the frozen-encoder + logistic-regression head, the integer HDC bundle (compaction, bit-exact head), and the fine-tuned encoder where a GPU exists. All but the last cost seconds of CPU per site, so running them side by side is free; each gets its own certificate and the one with the highest certified coverage at the operator's budget is promoted, the rest stay in shadow. One rule this needs: selection and certification must not use the same rows. Picking the best of N candidates on the calibration slice and then quoting that slice's bound is optimistic; either certify each candidate at delta/N (union bound, as the grid certifier already does over coverage levels) or select on one slice and certify on a second. The dedicated memory-student de-risk (S29: rows ladder to 15k, imbalance, deletion, query cost at 1M rows, byte-determinism) was written (`smokes/s29_memory_student/run.py`) but cancelled before producing results; the parallel-training design makes it a nice-to-have rather than a gate.

**S29 memory student at scale (2026-10-18, RTX 4090 pod 15 min $0.225 + Modal CPU est. $0.03; `smokes/s29_memory_student/RESULTS.md`).** Seeded Hopfield memory vs LR, 5 splits, 500 calibration rows, 5% budget. (1) **Ties at tens of labels, loses at 150.** With exactly k rows per label and every label seeded (Banking77 77 labels, CLINC45), seeded-memory minus LR certified coverage is -0.07 / +0.25 (Banking77, k=3 / 10) and +0.14 / -0.03 (CLINC45), none beyond 2 s.e.; on CLINC150 (150 labels) the memory certifies 0.28 to 0.33 less at k=10 (2.3 to 3.9 s.e.) and 0.15 to 0.19 less at 50 and 100 rows per label (6 to 10 s.e.), accuracy 3.5 to 4.3 points lower; Banking77 at 9,993 rows is a tie (0.858 vs 0.835). (2) **Imbalance: weight each class's vote by 1/its row count.** On a Zipf memory (12 to 172 rows per class) it lifts accuracy 0.880 to 0.905, rarest-20 recall 0.816 to 0.885, coverage 0.678 to 0.731, free on balanced data; capping rows per class (top 1 or 5) does not help. (3) **Query p50, one CPU thread, batch 1:** 0.31 ms at 1k rows, 1.17 ms at 10k, 17.1 ms at 100k, 271 ms at 1M (GPU 0.2 to 0.4 ms to 100k); hnswlib reads 1M rows in 0.15 ms but changes 4.3% of predictions. (4) **Deletion revokes:** deleting all rows of 10 labels revoked the certificate in 4 of 5 splits (traffic for the deleted labels is now always wrong), 20% random rows or every row with a common token in 1 of 5; the stale cutoff would have broken the 5% promise in the same splits, so a deletion must trigger a re-gate (13 to 34 ms for the memory on GPU). (5) **Byte-stable across processes:** three fresh interpreters give identical bytes on CPU (1 thread) and on GPU; bytes change with batch shape, CPU thread count and GPU `index_add`, never label + confidence to 3 dp; CPU and GPU differ. Net: the memory stays priority 1 for day zero, deletion, evidence rows and replay, with the 1/count rule; at 150 labels with tens of rows the parallel trainer should be expected to promote LR.
